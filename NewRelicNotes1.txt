Use New Relic APM
	Once the agent starts to report data to the UI successfully, admins can use that data to monitor and enhance application performance.

	First, check the overview of a selected application. Log in to the New Relic site and view the portal, which provides an index of monitored applications. Select the desired application to view an array of charts, tables and reports about the application's performance.

	One noteworthy overview entry is the application's user satisfaction, or Apdex, score. This measures the ratio of satisfactory and unsatisfactory response times. The ratio is presented graphically between zero -- completely unsatisfactory -- and one -- completely satisfactory. Phase 2: Installing and Configuring Agents

	New Relic uses "agents" that you install in your applications and infrastructure to collect performance data and send it to the New Relic platform. The installation process varies depending on what you're monitoring.

	Application Performance Monitoring (APM):

	Identify Your Application's Language/Framework: 
		New Relic supports a wide range of languages like Java, Python, Node.js, Ruby, PHP, .NET, Go, and more.
	Follow the Specific Agent Installation Guide: 
		New Relic provides detailed documentation for each language agent. You'll typically need to:
	Add a dependency to your project (e.g., using Maven, pip, npm, gem, Composer, NuGet).
	Configure the agent with your New Relic license key and application name (this is crucial for identifying your data in the platform). Configuration can often be done through environment variables, configuration files, or code.
	Restart your application.
	Example (Python - using newrelic package):


pip install newrelic
Then, configure using an environment variable:


	NEW_RELIC_LICENSE_KEY="YOUR_LICENSE_KEY" NEW_RELIC_APP_NAME="My Python App" python your_app.py
	Or using a newrelic.ini configuration file.
	Infrastructure Monitoring:

		Install the New Relic Infrastructure Agent: 
			This agent 
				runs on your servers (physical or virtual) and 
					collects data about 
						CPU usage, 
						memory, 
						disk I/O, 
						network traffic, etc.
		Follow the Installation Guide for Your Operating System: 
			New Relic 
				provides specific instructions for 
					Linux 
						(various distributions), 
					Windows, and 
					macOS. 
			This usually involves downloading and running an installation script or using package managers.
		The agent will typically 
			auto-detect many aspects of your infrastructure. 
		You might need to configure it with your license key.
	Digital Experience Monitoring (DEM):

		Real User Monitoring (RUM): 
			You'll typically add a 
				JavaScript snippet to the <head> or 
				just before the </body> tag of your web pages. 
			New Relic provides this snippet through its UI.
		Synthetic Monitoring: 
			You'll configure "monitors" within the New Relic UI to simulate user interactions with your website or APIs at scheduled intervals.
	Log Management:

		Configure Logging Integrations: 
			New Relic can collect logs from various sources. You'll need to configure your logging libraries or systems to forward logs to New Relic's logging endpoint, often using a logging forwarder agent (like Fluentd or Fluent Bit) or direct integrations.

Synthetic monitoring (also known as proactive or availability monitoring) in New Relic allows you to simulate user interactions with your applications and APIs from geographically diverse locations at scheduled intervals. This helps you proactively detect and resolve issues before they impact your real users.

Think of it as having automated testers constantly checking the availability and basic functionality of your critical services.

Key Concepts of New Relic Synthetic Monitoring:

Monitors: These are the core of synthetic monitoring. A monitor defines what you want to test, how often, and from where.
Monitor Types: New Relic offers various monitor types to simulate different scenarios:
Ping Monitor: Simple check to verify if a URL is reachable and responds within a specified time.
Simple Browser Monitor: Loads a web page in a real browser environment and verifies basic elements and performance.
Browser Monitor (Scripted Browser): Allows you to write more complex scripts using Selenium WebDriver to simulate multi-step user journeys (e.g., logging in, adding items to a cart, checkout).
API Test Monitor (Scripted API): Enables you to write scripts to test your APIs, including making HTTP requests, validating responses, and asserting specific conditions.
Multi-step API Monitor: Allows you to define a sequence of API calls to test complex workflows.
SSL Certificate Monitor: Checks the validity, expiration, and other details of your SSL/TLS certificates.
DNS Monitor: Verifies the resolution of your domain names.
  
Locations: You can choose from a wide range of global locations from which your monitors will run. This helps you understand the availability and performance of your application from different user perspectives.
Frequency: You can configure how often your monitors will run (e.g., every minute, every 5 minutes, hourly). The frequency impacts the granularity of your availability data and the number of synthetic checks performed.
Assertions: Within your browser and API monitors, you can define assertions to validate that your application is functioning correctly (e.g., specific text is present on a page, an API returns a specific status code or data).
Alerting: You can set up alerts based on the results of your synthetic monitors (e.g., if a monitor fails for a certain number of consecutive checks).
